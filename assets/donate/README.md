# 支持作者的接入说明

这个目录是给「支持作者」用的，程序不会往这里写任何东西，只读。
配置在 `src/config/app-info.json` 的 `donate` 字段。

## 推荐：走平台（爱发电）

```json
"donate": {
  "qrImage": "",
  "afdian": "https://afdian.com/a/你的ID",
  "sponsors": ""
}
```

填了 `afdian` 就会在「关于」面板里显示按钮，点击用系统浏览器打开。

为什么推荐平台而不是收款码：

- **可证明性**：平台订单上写着「赞助」，你能证明这笔钱是无偿赠与；静态收款码只有一笔转账记录，事后无法说明性质
- **税务痕迹**：平台侧有完整记录；静态码全靠自己申报，被问到时要自证
- **争议处理**：平台有既定的处理流程；静态码只能私下商量
- **不用往仓库放图**：转账二维码一旦提交就会永久留在 git 历史里，删了也能被 clone 出来

平台侧参数（以官方页面为准，可能变化）：抽成 6%、当月收入次月 1 号进余额、赞助成功后不可退款。

## 备选：静态收款码（自行承担风险）

如果你确实想直连微信/支付宝：

1. 把收款码存成 `assets/donate/wechat.png`
2. 在 `app-info.json` 里把 `qrImage` 填成 `assets/donate/wechat.png`
3. **不要 `git add` 这张图**——`.gitignore` 已经排除了 `assets/donate/*.png`，
   本地有图就显示、仓库里不留，但打包时仍会被打进安装包

三个前提：

- 截图必须裁掉昵称、头像、手机号，只留二维码本身
- 个人收款码开不出发票，公司用户无法报销
- 持续、多笔收款可能被支付机构判定为经营性收款而限额

## `sponsors` 为什么留空

GitHub Sponsors 需要 Stripe Connect 账户，中国大陆个人无法开通。字段留着是为了兼容，
填不进去也不用管，空字符串时界面不会显示那个按钮。

## 为什么不做应用内支付

个人开发者接微信/支付宝收款需要商户资质，应用内代收资金还涉及资金流向的合规问题。
这里只做「展示入口 + 跳转」，金额由用户在支付页面自行填写——程序不经手、不记录、不抽成。
