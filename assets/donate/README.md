# 支持作者的接入说明

这个目录是给「支持作者」用的，程序不会往这里写任何东西，只读。
配置在 `src/config/app-info.json` 的 `donate` 字段。

## 主通道：微信赞赏码（`qrImage`）

```json
"donate": {
  "qrImage": "assets/donate/wechat.png",
  "afdian": "https://afdian.com/a/ahleung",
  "sponsors": ""
}
```

选它是因为**零门槛**：扫码、输金额、付款，全程不用注册、不用登录。小额赞助的转化率全看这一步少几次跳转。

微信官方文档（`pay.weixin.qq.com` 收付款说明）里对赞赏码的定性，正好是我们需要的：

> 赞赏行为属于自愿赠与，不构成法律上的债务关系。

这比「平台订单写着赞助」更直接——性质由产品规则本身写死，不靠事后解释。

三个必须接受的硬限制：

- **单笔上限 200 元**（官方文档明确写死）。想支持更多的人只能走爱发电。
- **静态码用于远程收款是灰色地带**。央行 259 号文要求「禁止个人静态收款条码被用于远程非面对面收款」，而把码贴进 README / 程序就是远程场景。实践中普遍存在、未被大规模处置，但**随时可能被限额或静默失效**，且没有通知。
- **开不出发票**。企业用户、想报销的人走不通。

图片处理：

- 存成 `assets/donate/wechat.png`，**不要 `git add`**——`.gitignore` 已排除 `assets/donate/*.png`
- 但注意：打包时会进安装包，**安装包一发出去，这张码就等于公开了**。所以「留在 git 历史」在这条路上从来不是真问题，真正要接受的是「它会被任何人拿去用」
- 截图裁掉昵称头像，只留二维码；赞赏设置里的引导语建议写明项目名（上限 20 字），扫码页才有上下文

## 备选：爱发电（`afdian`）

```json
"afdian": "https://afdian.com/a/ahleung"
```

填了就在「关于」面板里多一个按钮，点击用系统浏览器打开。它补的正是赞赏码补不上的三块：

- **金额不封顶**
- **有订单记录**，能导出、能自证
- 支付宝也能付

平台侧参数（以官方页面为准）：抽成 6%（创作者得 94%）、当月收入次月 1 号进余额、赞助成功后不可退款。
注意它没有自动扣款能力（微信/支付宝的「预授权」资质拿不到），所谓「按月」是用户预付 N 个月、平台逐月释放。
**想让钱一次到账，只能让用户选 1 个月时长。**

## `sponsors` 为什么留空

GitHub Sponsors 需要 Stripe Connect 账户，中国大陆个人无法开通（支持地区列表里有港澳，没有大陆）。
字段留着是为了兼容，空字符串时界面不会显示那个按钮。

## 为什么不做应用内支付

个人开发者接微信/支付宝收款需要商户资质，应用内代收资金还涉及资金流向的合规问题。
这里只做「展示入口 + 跳转」，金额由用户在支付页面自行填写——程序不经手、不记录、不抽成。
